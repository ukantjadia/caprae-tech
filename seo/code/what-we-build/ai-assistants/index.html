AI can't check its own work. A human can.

Every automation we build has a grader. Some checks are automatic, but the final measure is always a person scoring the same work the AI did. When the two disagree, the person is right and the system gets fixed.

Three ways to grade AI

Code grader

Fixed checks a program can run: is every field filled, is the format right, is the number valid. Fast and cheap, but only catches what you can write a rule for.

Model grader

A stronger model reviews the work against written criteria. Good for judgment at scale, but AI checking AI is never the final word.

The source of truth

Human grader

A person scores the same work on the same criteria. Their score is the one the system is measured against.

In practice we combine them: code and model graders check every run, and a human grades a sample.

The loop

  1. 1AI does the workScores, writes, sorts or researches.
  2. 2Automatic checksCode and model graders review every output.
  3. 3A human grades a sampleSame items, same criteria, scored independently.
  4. 4Measure the gapWhere does the AI disagree with the human, and why?
  5. 5Fix and re-testChange the prompts, the steps or the model, then run it again.
↺ repeat until the gap is small enough to trust
Case study · Call Intelligence

How we closed the gap between the AI and a human grader

Run 1, gap 3.1. Human graders scored the same set of call recordings as the AI. The AI was too strict on good calls (it almost never gave a 9 or 10) and too generous on bad ones.

Run 2, gap 1.3. We stopped pushing the model toward low scores. Instead of one prompt judging the whole call, we split the call into phases and gave each phase to its own sub-agent, the same way our human graders split their scoring criteria.

Now, gap 0.3. We studied where the two still disagreed and made a round of smaller fixes.

Agents that run a process

The right model for each step, not the most expensive one everywhere.

We've built extensively on Anthropic's and OpenAI's APIs, and we use DeepSeek and Gemini where they give the same result for less. Before anything goes live, we measure how many tokens each step uses and what it costs, then use a cheaper model wherever the output holds up. You get the best model where it matters, and a lower bill everywhere else.
